# The `/api` reference

Audience: a developer integrating against the HTTP API. Romeka S keeps Omeka S's `/api` surface, so a client written for Omeka S works unchanged.

Generated by `docs/gen.sh` from the `omeka-api` source. Do not edit by hand: change the source, run `cd docs && ./gen.sh`, and commit both the source change and this file. `./gen.sh --check` fails when this file is stale.

## Requests

Every `/api` request takes the API key as two query parameters, `key_identity` and `key_credential` (`crates/omeka-api/src/auth.rs`). With neither, the request is anonymous.

A write (POST, PUT, PATCH) must send `Content-Type: application/json` or `multipart/form-data`; anything else is 415. A GET and a DELETE need no content type.

A `property` row carries `joiner`, `property`, `text`, `type` (`crates/omeka-api/src/read/query.rs`); a row with no usable value is dropped.

## Access

Search and read (`Api::allow` in `crates/omeka-api/src/read/mod.rs`).

| Resources | Allowed caller |
| --- | --- |
| `users` | any authenticated caller |
| `value_annotations`, `jobs`, `modules` | a caller whose actor has view-all |
| every other resource | everyone, including anonymous callers |

Create, update and delete (`write::access::adapter` in `crates/omeka-api/src/write/access.rs`). One row per resource and one grant per operation. The admin roles pass every row, so a cell lists the other roles that row admits, and a resource with no row is admin-only. A resource with no write handler passes this check and reaches the 501 the route table marks.

| Resource | Create | Update | Delete |
| --- | --- | --- | --- |
| `items` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` |
| `item_sets` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` |
| `media` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` |
| `assets` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` | `author`, `reviewer`, `editor`, `site_admin`, `global_admin` |
| `resource_templates` | `author`, `editor`, `site_admin`, `global_admin` | `author`, `editor`, `site_admin`, `global_admin` | `author`, `editor`, `site_admin`, `global_admin` |
| `vocabularies` | the admin roles | the admin roles | the admin roles |
| `resource_classes` | the admin roles | the admin roles | the admin roles |
| `properties` | the admin roles | the admin roles | the admin roles |
| `jobs` | the admin roles | the admin roles | the admin roles |
| `custom_vocabs` | `editor`, `site_admin`, `global_admin` | `editor`, `site_admin`, `global_admin` | `editor`, `site_admin`, `global_admin` |
| `users` | the admin roles | `researcher`, `author`, `reviewer`, `editor`, `site_admin`, `global_admin` | the admin roles |
| `sites` | any caller | any caller | any caller |
| `site_pages` | any caller | any caller | any caller |

Delete then checks the entity rule: `write::access::resource_entity` for items, item sets, media and assets (an editor or an admin role may remove any row, an author or a reviewer only a row they own), `owned_entity` for sites and site pages (an admin role any row, everyone else only their own, so an anonymous caller is refused; a `site_permission` role of `admin` also grants a site update and `editor` or `admin` a page write or delete), `user_entity` for users (an admin may not remove their own account, and a site admin may not remove another admin), and `vocabulary_entity` for vocabularies (a global admin any row, a site admin only one they added). Update carries `resource_entity_update`: a reviewer and up may change any row of items, item sets, media, assets and resource templates, and an author only a row they own.

## Errors

An error body is `{"errors": {"<field>": "<message>"}}`, or a list of messages for one field (`crates/omeka-api/src/errors.rs`). Every error kind and the status it answers:

| Error kind | Status | When |
| --- | --- | --- |
| `ApiError::BadRequest` | 400 | the body is not a JSON object, or a member the resource rejects |
| `ApiError::PermissionDenied` | 403 | the caller's role does not hold the operation |
| `ApiError::NotFound` | 404 | an unknown resource name, or a row the caller may not see |
| `ApiError::Conflict` | 409 | the request clashes with stored state, such as deleting a job a running import holds |
| `ApiError::StalePage` | 409 | Romeka: a site page `PUT` or `PATCH` whose `o:modified` is not the stored page's; the error object adds the stored `o:modified` and `o:user` (`o:id`, `o:name`) of who saved it. A body without `o:modified` is never refused |
| `ApiError::MethodNotAllowed` | 405 | the method is not routed on that path shape |
| `ApiError::UnsupportedMediaType` | 415 | a write body whose Content-Type is neither JSON nor multipart |
| `ApiError::Validation` | 422 | a body member failed validation, keyed by member |
| `ApiError::MergedValidation` | 422 | a body member failed validation, with one entry per failing sub-entity |
| `ApiError::NotImplemented` | 501 | a route with no handler yet |

## Web Annotation Protocol

These routes are not `/api` and are not parsed from `omeka-api`: they are the W3C Web Annotation Protocol server of `crates/omeka-server/src/annotations/`, over the domain service in `crates/omeka-api/src/annotation/`. A page of a media is also the IIIF `AnnotationPage` its canvas references, so one document serves both standards.

| Method | Route | Answer |
| --- | --- | --- |
| `GET`, `HEAD` | `/annotations/media/{id}/` | the WAP container, 200 |
| `POST` | `/annotations/media/{id}/` | 201 and the stored annotation; 200 on a replay of one `Idempotency-Key` |
| `GET`, `HEAD` | `/annotations/media/{id}/page[?after={a}]` | one keyset page, 200 |
| `GET`, `HEAD` | `/annotations/{a}` | one annotation, 200 |
| `PUT` | `/annotations/{a}` | 200, `If-Match` required |
| `DELETE` | `/annotations/{a}` | 204, `If-Match` required |
| `GET` | `/annotations/item/{id}/counts` | 200, the note count of every file of the item the caller may read |
| `OPTIONS` | `/annotations/...` | 204, the CORS preflight |

The counts document is Romeka's own, for the admin's item page: `{"media": {"<media id>": {"count": N, "writable": true|false}}}` under `Cache-Control: no-store`, one entry per media of the item the caller may read, in the item's order. `count` is the `total` the file's own container states, and `writable` is whether that container would accept a `POST`, so the page draws a card from this answer and reads one container only for a file whose notes it shows. A media the caller may not read is absent, as its container is a 404, and an item with no such media answers an empty `media` object. It is plain JSON rather than a WAP document, it carries `Cache-Control: no-store`, and it sends no CORS headers: only the admin's own page reads it.

The caller is the session cookie or the `/api` key pair; reading a media reads its notes, and holding the media-update grant writes them. Every answer carries `Access-Control-Allow-Origin: *`, `Vary: Accept, Cookie, Prefer`, `Cache-Control: no-cache` and a strong `ETag`: `"r<revision>"` for a note, and `"p"` with 16 hex characters of a SHA-256 over the content type and the body for a container or page. `If-Match` compares strongly, so a weak tag is a 412 and a missing one a 428. `If-None-Match` on a container or page is a 304. A create replayed with the same `Idempotency-Key` is a 200 and the same row; the key with a different draft is a 422.

Two headers state what the documents do not. `Romeka-Surface` is an RFC 8941 item naming what a selector may address: `image; width=…; height=…; service="…"` for a stored image, `time[; duration=…]` for audio and video, with `; width=…; height=…` for a video whose frame size is known (the pixels a box on its frames is drawn in), or `whole`. A box on a video frame is one `FragmentSelector`, `xywh=pixel:x,y,w,h&t=start,end`; a box with no range, or any shape on audio, is a 400. `Romeka-Canvas` is the media canvas IRI a create targets, so an empty container can still make its first note. `Romeka-Track-Ids` lists the numeric ids of the caption rows on the page it answers, and is absent when there are none. `Allow` says which of these methods the caller holds.

A 400 carries the annotation service's plain English sentence in the upstream error document, `{"errors": {"error": "…"}}`: "This media takes notes about the whole file only." for a selector the media's surface does not take, and the matching sentence for a box outside the canvas, a time range past the duration, or a document that is not an annotation.

## The embed frame

`GET /api/romeka/media/{id}/render` answers the server's own render of one media as a complete HTML document, which the admin media stage puts in a sandboxed frame (`crates/omeka-server/src/media_render.rs`). Upstream's admin calls `$media->render()` for the same reason and has no route for it.

Only an oEmbed or HTML media answers; any other kind is a 415 whose error document names the media's renderer. A media the caller cannot see, an id that names no media, and an id that is not a number are a 404, as they are on the media read. The caller is the session cookie or the API key pair, by the same visibility rule the API applies to a media and its item.

The document carries the media's title, one `<base href>` on the server root, and the purified render. Its headers are part of the contract:

| Header | Value |
| --- | --- |
| `Content-Type` | `text/html; charset=utf-8` |
| `Content-Security-Policy` | `default-src 'none'`; `script-src 'none'`; `style-src 'unsafe-inline'` for the frame's own base rule set and the `style` attributes the purifier keeps; `base-uri 'self'`; `form-action 'none'`; `frame-ancestors 'self'`; `img-src 'self'` plus the `http` and `https` origins the fragment's `img` sources name; `frame-src` the origins its `iframe` sources name. No source expression is wider than the render itself |
| `X-Frame-Options` | `SAMEORIGIN` |
| `Cache-Control` | `private, no-cache` |
| `Vary` | `Cookie` |

No answer sets a cookie.

## Retrying one media's access copy

`POST /api/romeka/media/{id}/derivatives/retry` re-queues one media's `access_copy` row after the tool that makes it failed, or after a tool the decision found missing was installed (`crates/omeka-server/src/media_derivatives.rs`). It answers the media document the read route builds, whose `o-module-romeka:access.state` is `pending` again, and starts the install's one derivative worker through the same dispatcher a create uses. The route takes no body.

The caller needs the media update grant: a global or site administrator, an editor or a reviewer, or an author whose own row it is; anyone else gets the 403 the media write gets. A media the caller may not see and an id that names no media are the media read's 404. A row that is already waiting or ready, and a row settled because the original is what the reader gets, has nothing to make again and answers 409 `server.noDerivativeToRetry`, because the document would not change.

Upstream has no such route: it makes every derivative inside the request and has nothing to retry.
