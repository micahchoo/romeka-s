# Compatibility with upstream

Audience: a reviewer or an operator deciding how far this port can stand in for an Omeka S installation.

This page is the map. The measurements live in generated artifacts under [`../verification/`](../verification/), and
this page links them rather than repeating numbers that change every time a unit lands.

## The frozen pair

A compatibility claim is a claim about a pair: upstream
[`omeka/omeka-s`](https://github.com/omeka/omeka-s) at commit `5e413f009c447f4b587803ab23a9cec7d228f6e8` (2026-10-16) and
this port at a named commit. [`../README.md`](../README.md) and [`../DESIGN.md`](../DESIGN.md) record the freeze, and
[`../VERIFY.md`](../VERIFY.md) is the definition of what "complete" means.

The fidelity rule from [`../DESIGN.md`](../DESIGN.md): downstream semantics come from upstream source, not from
documentation or memory, and where upstream source and `DESIGN.md` disagree, upstream wins and the disagreement is
reported.

## What a reader of this port can check themselves

```
./verify.sh                                  # the whole gate
./verify.sh --verification                    # the matrix, the ledger, the scenario diff
verification/upstream-inventory/check.sh --execute
verification/ledger/check.sh --execute
verification/scenarios/run.sh                 # against a started oracle
verification/scenarios/serve_port.sh          # the port against the committed goldens
```

The rule that makes these worth running is in [`../VERIFY.md`](../VERIFY.md): a ported row needs a proof the checker
reruns, and a verdict of INCONCLUSIVE is not a pass. An agent's report is a claim; these scripts are the evidence.

## The differences the port states about itself

These are deliberate, and each is named in the code rather than discovered. The compat matrix, when it lands, is the
complete list.

| Difference | Where it is stated |
| --- | --- |
| SQLite is the only storage engine; parity is behavioural, not SQL-level | [`../DESIGN.md`](../DESIGN.md), Decisions |
| The admin is a strict-TypeScript SPA over the same `/api`, not server-rendered PHP views; workflow parity, not pixel parity | [`../DESIGN.md`](../DESIGN.md), Decisions |
| Public sites render in Rust through a `Theme` trait; PHP themes are not ported | [`../DESIGN.md`](../DESIGN.md), Decisions |
| Module extension is a Rust registry, not a PHP module loader | [`../DESIGN.md`](../DESIGN.md), Decisions |
| The port answers no 401: a bad or missing key leaves the caller anonymous, and the access check answers 403 | [`api.md`](api.md), Errors |
| `GET /api/data_types/<unknown>` is a 404 where upstream throws and answers 500 | `../crates/omeka-api/src/read/meta.rs` |
| User passwords are stored with PBKDF2-HMAC-SHA256 because no bcrypt crate was available; API key credentials do use bcrypt, so the key verifier matches upstream | [`../crates/omeka-cli/README.md`](../crates/omeka-cli/README.md) |
| `omeka import media` derives `media_type` from the file extension; upstream sniffs the content with `finfo` and applies its alias table | [`../crates/omeka-cli/README.md`](../crates/omeka-cli/README.md) |
| Thumbnails come from the `image` crate, not GD; the port keeps GD's two strategies and the JPEG output, so a derivative can differ in bytes while matching in size | [`../crates/omeka-cli/README.md`](../crates/omeka-cli/README.md) |
| Fulltext search runs on SQLite FTS5; ranking differs from MySQL's and is excluded from differential matching | [`../DESIGN.md`](../DESIGN.md), Exclusions |
| `/s/:slug/item-set/:id` renders the item-set view; upstream's `site/item-set` route reaches the item browse | [`../crates/omeka-server/README.md`](../crates/omeka-server/README.md) |
| No `site_setting`, `site_block_attachment` or site-scoped item filter repository yet, so some blocks render with upstream defaults or empty | [`../crates/omeka-server/README.md`](../crates/omeka-server/README.md) |

## What completeness does not cover

[`../DESIGN.md`](../DESIGN.md) fixes the exclusions, and the matrix's `excluded` rows carry a reason and a date each:
third-party modules and themes, Laminas and Doctrine internals, full translation catalogs, live external services
(oEmbed, YouTube, remote IIIF), MySQL fulltext ranking particulars, mail delivery, admin pixel parity, and the
reference infrastructure itself (`source/omeka-s`, `oracle/`).

An exclusion is a reviewable decision, not a silent gap. [`../ROADMAP.md`](../ROADMAP.md) lists what closing each one
would take.
